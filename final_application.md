## Функциональные требования

### 1. Оценка решения по критериям
Для оценки решений используются 5 Ridge-моделей, обученных на TF-IDF. Каждая модель отвечает за оценку определенного критерия:
- Анализ ЦА
- Проработка решения
- Финансовая модель и метрики
- Анализ рисков
- Доказательства

**Метрики качества моделей (MAE):**

| Модель | MAE Val | MAE Test |
| :--- | :--- | :--- |
| Оценка анализа ЦА | 0.44 | 0.52 |
| Оценка проработки решения | 0.48 | 0.57 |
| Оценка финансовой модели и метрик | 0.44 | 0.52 |
| Оценка анализа рисков | 0.43 | 0.57 |
| Оценка доказательств | 0.45 | 0.57 |
| **Общая оценка** | **—** | **0.33** |
| *Общая оценка baseline (медиана)* | *1.00* | *1.07* |

### 2. Проверка принадлежности решения к кейсу
Логистическая регрессия возвращает вероятность принадлежности решения к каждому из 10 кейсов, доступных в приложении. Если вероятность принадлежности решения к кейсу, к которому оно было отправлено, меньше заданного порога (порог подбирался отдельно для каждого кейса), модель не допускает решение к проверке. 

Целевой показатель **Recall**: пороги подбирались так, чтобы правильные решения отклонялись не более чем в 3% случаев. 
*В случае недопуска пользователь получает сообщение:* «Ваше решение не соответствует выбранному бизнес-кейсу».

### 3. Фильтр бессмысленных решений
Модель LinearSVC, обученная на TF-IDF, классифицирует решения на осмысленные и бессмысленные. Порог допуска подбирался для максимизации **Recall** (так как хуже не допустить хорошее решение, чем оценить бессмысленное, чтобы не демотивировать школьника). 
**Метрики:** Recall = 0.990, Precision = 0.783. 
*В случае недопуска пользователь получает сообщение:* «Решение пока нельзя оценить, так как оно не содержит конкретики».

### 4. Фильтр эталонных решений
С помощью косинусной близости оценивается близость TF-IDF эталонного и отправленного решений. Если она выше определенного порога, то решение до оценки не допускается. Это сделано, чтобы участник не мог отправить эталонное решение (которое выдаст максимальный балл), так как это нечестно по отношению к другим пользователям при составлении рейтинга. 
*В случае недопуска пользователь получает сообщение:* «Ваше решение слишком похоже на эталонное, подготовьте собственное решение».

### 5. Генерация обратной связи (Пояснение оценки)
После выставления оценок система использует GigaChat для написания комментариев к полученным баллам и предоставления пользователю советов по исправлению решения и повышению итогового балла. 
*Важно:* GigaChat не изменяет выставленные моделью оценки и не генерирует за пользователя готовый ответ, а только дает рекомендации.
