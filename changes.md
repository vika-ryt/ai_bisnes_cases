# Отчет об изменениях

**1. Функциональное требование: Проверка принадлежности решения к выбранному кейсу**

**Краткое описание изменения:** 
Планировалось: оценка решений без строгой проверки соответствия текста выбранному кейсу (или проверка осуществлялась только по названию). 
Стало: добавлена модель логистической регрессии. Она возвращает вероятность принадлежности решения к каждому из 10 кейсов. Если вероятность принадлежности к выбранному кейсу ниже заданного порога (подбирался отдельно для каждого кейса с целевым recall, чтобы правильные решения отклонялись не более чем в 3% случаев), решение не допускается к проверке. Пользователь получает сообщение: «Ваше решение не соответствует выбранному бизнес-кейсу».

**Причина:** 
Необходимость отсеивать решения, которые не относятся к выбранному кейсу, чтобы участники не могли получить баллы за отправку нерелевантных текстов.

---

**2. Функциональное требование: Фильтр эталонных решений**

**Краткое описание изменения:** 
Планировалось: базовая оценка решений без защиты от копирования эталонов.
Стало: добавлен фильтр на основе косинусной близости TF-IDF. Система оценивает близость отправленного решения к эталонному. Если она выше определенного порога, решение до оценки не допускается. Пользователь получает сообщение: «Ваше решение слишком похоже на эталонное, подготовьте собственное решение».

**Причина:** 
Предотвращение нечестного получения максимального балла путем копирования эталонного ответа. Это необходимо для сохранения честности при составлении рейтинга участников.
